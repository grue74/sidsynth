# SID808

An 808-style drum machine for the C64 with an **8580 SID**: synthesized
drums played from MIDI, and a 16-step pattern sequencer.

Sister project of SID303. Both build on the shared SID synth core in
`core/`, a git submodule (repo `synthcore`): start-up, interrupts, MIDI in
and out,
parameter system with MIDI and paddle learn, keyboard, parameter screen and
test feeders. `core/README.md` lists what a synth provides (hooks, parameter
tables, key map). Clone with `git clone --recurse-submodules`.

## Plan

0. **Sound prototype:** kick, snare, clap, hats and cowbell synthesized on
   the SID, recorded in VICE, to judge the sound before building the rest
   (done: all eleven 808 sound circuits, thirteen sounds; recordings in
   `demos/`, design notes in `docs/design.md`).
1. **Shared core** with SID303, as a git submodule (done).
2. **MIDI drum module:** General MIDI drum notes, velocity = accent, a
   parameter page per sound (done: Level, Tune, Decay, Tone per sound on
   the parameter screen, `docs/design.md` 10).
3. **Step sequencer:** 16 steps, three levels per step, tempo, swing,
   patterns and chains, MIDI clock in and out, patterns saved to disk
   (done: the step grid editor, song mode, live record, MIDI clock in,
   MIDI out, disk save/load; `docs/sequencer.md`).

### Voices

The SID has three voices and the 808 eleven sound circuits, so the voices are
shared: a new hit takes the voice already playing its choke group (closed
hat chokes open hat), else an idle voice, else the quietest one, weighted by
how important the sound is. The filter belongs to the newest hit that wants
it. Each sound is a step program generated by `tables.py`; the engine runs
at 500 Hz. Details: [docs/design.md](docs/design.md).

## Building

`sh build.sh` (needs Python and 64tass): `sid808.prg`, `sid808-test.prg`
(plays every sound soft and hard, then an 808 beat), `sid808-track.prg`
(a drum track) and `sid808.d64`.

Versions: `VERSION` holds the release number (major.minor.patch); the
program's title row shows it with the build number (the git commit count,
+1 with uncommitted changes), e.g. `v0.9.0 build 30`, so a report names the
exact build. `build.sh` also writes `version.txt` for the manual and web
page. A release: set `VERSION`, commit, `sh build.sh`, `python
docs/manual.py`, `python make_site.py` in `projects/sidsynth`, commit the manual, and tag the
commit `v<version>`.

User manual: `docs/SID808-manual.pdf` (`python docs/manual.py`, needs
reportlab). Web page: `python make_site.py` writes SID808's page (needs
ffmpeg: the demos, downloads and technical details) into the SidSynth site,
`../sidsynth/site/sid808/`. The site is one for the whole family: build and
upload it from `projects/sidsynth` (its `make_site.py` runs this one).

Also on the disk, for listening tests (`docs/listening.md`):
`sid808-problems.prg` (the places where the engine might go wrong, one at a
time), `sid808-stress.prg` and `sid808-stress-max.prg` (the sequencer under
load, to judge the tempo).

`demos/`: VICE recordings (reSID 8580). `demo-4` and `track-6` are the two
test builds on the current engine (sound page, Tone, click fix);
`problems-1`, `stress-1` and `stress-max-1` the listening tests
(`docs/listening.md`). `bass-and-drums-3` (video and sound) is a piece composed for both machines:
SID808's drums on its own sequencer (`TEST_SONG=1`, tables.py `DEMO_*`) and
SID303's bass on a second C64, side by side; `python
demos/bass_and_drums.py` builds, records, aligns and renders it.
`bass-and-drums-1` is an early build with SID303's test line over the
drum track. `demo-3` and `track-5` (video and
sound) are the builds with the ring-modulated cowbell before the sound page
(`demo-2` and `track-4`: the same before it). The `*-compare`
files are the A/B tests behind sound choices noted in `tables.py`.
